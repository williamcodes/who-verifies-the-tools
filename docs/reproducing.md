# Reproducing the checks

## Offline verification

From the repository root, with Python 3.12 or newer:

```bash
python3 -m experiment verify
```

The standard library is sufficient. The same command works with `python3 -S -B`
to disable site packages and bytecode writes. Individual suites remain available:

```bash
python3 -m unittest tests.test_offline
python3 -m unittest discover -s tests -t .
```

## Python lint checks

Run the same pinned Ruff version as CI:

```bash
uvx ruff@0.16.7 check .
uvx ruff@0.16.7 format --check .
```

Without `uv`, install `ruff==0.16.7` in your development environment and run
the same commands with `python3 -m ruff` instead of `uvx ruff@0.16.7`.
Ruff is a development tool; offline verification still
uses only the standard library.

[ruff.toml](../ruff.toml) checks all Python files for errors, import ordering,
modern Python idioms, common mistakes, and function complexity. Narrow exceptions
preserve the verbatim historical formatters and the hash-checked builder fixture.
Run `uvx ruff@0.16.7 format .` to format maintained code. Formatting excludes
historical formatters, frozen prompts, and the original builder fixture.

Optional local hooks apply Ruff's safe lint fixes and formatting before a commit:

```bash
uvx pre-commit install
uvx pre-commit run --all-files
```

Keep the Ruff version in `ruff.toml`, CI, and `.pre-commit-config.yaml` in sync.

The transport's shared log stays open across calls. The shared worker loop owns
the client and closes it after workers finish, including on failure.

## Replay the frozen artifacts

```bash
python3 -m experiment.build_manifest --replay --output-dir scratch/replay
```

This reconstructs the final manifest and checker report and copies the older preview
unchanged. It checks all three files against their pre-refactor hashes before writing.
F1/F2 replay both formatter versions from recorded tool results. F3/F4 derive A from
frozen B; their complete database inputs are unavailable. The original database
queries and selection rules are tested separately on synthetic SQLite rows and tool
results, with expected outputs generated by the original builder at a fixed time.

## Recompute saved analysis in scratch space

Preserve the relative `cases/` and `runs/` layout expected by the historical analyzer:

```bash
mkdir -p scratch/analysis/runs
cp -R data/cases scratch/analysis/cases
cp -R data/runs/20260826T015731Z-full scratch/analysis/runs/
python3 -m experiment.analyze scratch/analysis/runs/20260826T015731Z-full
```

The verifier-fixed run can be copied and analyzed the same way. Analysis writes
`analysis.md` and, for a large enough agent run, `human_sample.md`. Automated tests
compare both reported runs with outputs produced by the original analyzer.

## Try the human-grading interface

```bash
python3 -m experiment.grading --output-dir scratch/my-grades
```

Open `http://localhost:8765`. The interface displays facts, the question, allowed and
forbidden claims, and the answer. It reveals agreement after the sample is complete.
Grades resume from the chosen directory. The recorded study directory is refused as
an output destination. Blinding is an interface convention: the hidden form key
contains model and condition metadata and can be inspected in page source.

## Historical source and live model runs

Offline verification does not need these paths. The original script entrypoints and
live-run modes remain available for inspecting the protocol:

```bash
python3 experiment/harness.py --help
python3 experiment/build_manifest.py --help
```

The model harness reads `OPENROUTER_API_KEY` from a local `.env` file and calls
OpenRouter. Running a live mode spends API credit. Recorded model identifiers and
settings are frozen; availability and a new run's outputs are not guaranteed.
New observations go under `data/runs/`; resume uses the run ID and
rejects changed cases, prompts, or settings. No live requests were made during this
refactor.

The database builder without `--replay` requires the external archive application,
its dependencies, and its database. It pins source commit
`8364f2281ab31c9f13a0486a0395221da80fab53`, checks guarded files, and checks schema
version read-only before constructing the database manager. Its legacy config expects
the source repository as the working directory. `--allow-dirty` marks provenance
unverified and cannot bypass a migration mismatch. `--output-dir` redirects generated
files; otherwise the historical command writes to `cases/`.

That database path was not run during this refactor. Its time-dependent metadata and
later manual provenance annotation prevent a literal historical rebuild from the
public artifacts alone. See the [verification report](verification.md).
