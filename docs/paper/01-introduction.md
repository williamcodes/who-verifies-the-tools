# 1. Introduction

A user asks a production research agent to search an archive for records from a year. Its database contains 4,772 matching documents, but the tool only returns up to 20. In the tool's own words, the output begins "Found 20 document(s)", then lists them. Every sentence it prints is true. It did find 20 documents. It just did not specify that they were the first 20 of 4,772. The agent does not have direct access to the database, nor does it have access to the codebase to see the cap in the code. All it has is the words returned by the tool. So it reviews the 20 documents and moves on, completely oblivious to the mountain of unexplored results just behind that limit.

How do we catch this? A typical verifier cannot help because it would not have database and codebase access either. It would simply compare the agent's answer to the data returned by the tool and conclude that it was accurate. And with the information given, the verifier would be right. Neither agents nor verifiers can recover a fact that the tool's formatter simply leaves out. We call a formatter like this warped: the tool worked, and the wording bent the picture of what it did.

Other outputs from the same production system had related failures. An in-document search said "Searched the FULL text" after scanning no more than 1,000,000 characters. The system could present an estimated page number as if confirmed when the label was absent. Separate document and scan numbering let a document number resolve as a valid scan number for a different item. These cases established that the failures occurred in production. They did not establish how the wording affects agent claims or verifier judgments more generally.

We asked whether changing the wording of a fixed tool result changes what agents claim and what verifiers accept. We paired each incomplete description with a description of the same result that stated its scope, completeness, uncertainty, or identifier source. Agents answered from the output, and verifiers judged whether the answers were supported. The method stated what each output had to disclose, and a checker used fixed rules to verify which disclosures were present.

We collected 1,200 agent runs across three model families. Adding the missing information reduced unsupported agent claims by 62 to 92 percentage points for search coverage, result totals, and estimated values. Agents continued to reuse document numbers as scan numbers despite labels that named the numbering system. In a fixed-answer measure, the paired wording changed all 90 verifier verdicts, 30 unsupported answers each judged by three verifiers, from acceptance to rejection.

We also wrote a short audit prompt for a general-purpose coding agent. On the production system's source code, the agent rediscovered the defects that remained live and found additional warped formatting. Separate runs on OpenClaw and Hermes found warped formatters in each system.
